## ❓ 疑问和需要确认的问题

### ❓ 问题1：赠点扣除逻辑不一致

**代码位置**: 行3041-3043

```php
$money = $services->point;
if (!empty($giftPoint) && $path == 'leave') {  // ← 只在leave时扣除
    $money = max($money - $giftPoint['gift_point'], 0);
}
```

**疑问**：
1. **为什么只在 `leave` 时扣除赠点，`down` 时不扣除？**
   - 这会导致玩家可以多次 `down` 下分，把赠点全部套现
   - 最后 `leave` 时才扣一次

2. **没有检查流水条件**：
   - 老虎机有检查：`if ($money < $giftPoint['open_point'] * $giftPoint['condition'])`
   - 钢珠机没有这个检查

**示例场景**：
```
玩家操作：
1. 上分100（含赠点20，流水要求3倍）
2. 玩游戏，赢了80 → 机台分数180
3. down 下分100 → 拿走100（不扣赠点）
4. down 下分50 → 拿走50（不扣赠点）
5. leave 弃台 → 拿走30-20=10（扣除赠点）

结果：
- 玩家拿走：100+50+10 = 160
- 本应扣除：20（赠点）
- 但因为down时不扣，玩家多拿了50
```

**需要确认**：
- 这是有意设计还是bug？
- 是否应该在每次下分时都检查并扣除赠点？

### ❓ 问题7：分布式锁的超时时间

**代码位置**: 行2912

```php
$lock = Locker::lock($actionLockerKey, 8, true);
```

**疑问**：
1. **超时8秒是否足够？**
   - 机台指令可能需要多次网络调用
   - 弃台：2-5个指令 + 2个查询指令 + 2个清零指令
   - 每个指令可能需要1-3秒
   - 总时间可能超过8秒

2. **超时后锁自动释放，可能导致什么问题？**
   - 如果A操作还在执行，锁已释放
   - B操作获取锁，开始执行
   - 可能导致并发问题

**建议**：
- 增加超时时间到15-20秒
- 或者根据操作类型动态调整

### ❓ 问题8：Redis 状态更新的时机

**当前逻辑**（修复后）：

```
1. 弃台指令（机台状态变化）
2. 读取机台状态
3. 清零机台
4. 数据库事务开始
   - machineWashZero（玩家+钱）
   - 更新 keeping 相关字段到 Redis ← 在事务内
5. 数据库事务提交
6. 更新 gaming 相关字段到 Redis ← 在事务外
```

**疑问**：
1. **为什么 keeping 字段在事务内更新，gaming 字段在事务外更新？**
   - 是否应该统一？

2. **如果数据库事务失败（rollback）**：
   - keeping 字段已经更新到Redis（事务内）
   - 但数据库rollback了
   - 会导致Redis和数据库不一致

**建议**：
- 所有Redis更新都放在事务提交后
- 或者所有Redis更新都放在事务提交前
